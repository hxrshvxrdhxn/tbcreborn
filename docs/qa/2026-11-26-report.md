## 3. Test Execution Matrix

### 3.1 Device & Browser Configurations
The Playwright test suite was executed against the following 7 browser and device targets:
1. **Desktop Chromium (1920 × 1080)**: High-resolution desktop baseline.
2. **Desktop Chromium (1366 × 768)**: Standard laptop display resolution.
3. **Desktop Firefox (1920 × 1080)**: Gecko rendering engine verification.
4. **Desktop WebKit (1920 × 1080)**: Safari WebKit rendering engine verification.
5. **Mobile iPhone 14 (390 × 844, DPR 3, touch)**: iOS Safari mobile viewport.
6. **Mobile Pixel 7 (412 × 915, DPR 2.625, touch)**: Android Chrome mobile viewport.
7. **Tablet iPad Mini (768 × 1024, DPR 2, touch)**: Medium tablet touch viewport.

### 3.2 Visual & Layout Verification (84 Tests)
Scanned 12 primary page types across all 7 devices:
- `/` (Home)
- `/services` (Services Overview)
- `/services/aeo-seo-geo` (AEO / SEO / GEO Pillar)
- `/services/custom-software-development`
- `/services/business-automation`

- `/products/meridian`
- `/about`
- `/contact`

**Automated Assertions Per Target**:
- No horizontal overflow (`document.documentElement.scrollWidth <= clientWidth`).
- Zero console exceptions (`window.onerror` and unhandled rejections).
- Zero unclicked YouTube iframes rendered on initial load.
- Full-page PNG screenshot captured and stored in `qa/screenshots/`.

### 3.3 User Journey Tests (9 Tests)
- **Journey 1: Home → Service → Contact**: Navigated from homepage to Business Automation and opened Contact consultation form with preselected service.
- **Journey 2: Home → Product → Book Consultation**: Navigated from homepage to Distil product page and followed CTA to booking modal.
- **Journey 3: Blog Pagination & Post Navigation**: Verified page 1 → page 2 navigation, visited a post, and confirmed live related post links.
- **Journey 4: How-To Guide Search**: Queried guide index with instant autocomplete search.
- **Journey 5: AEO Pillar → Free AI Visibility Check**: Seamless transition from AEO service pillar to visibility audit form.
- **Journey 6: Mobile Menu Navigation**: Verified hamburger drawer open, close, and link navigation on mobile viewports.
- **Journey 7: Footer Link Integrity**: Verified all footer links resolve to valid, active internal routes.
- **Journey 8: 404 Error Experience**: Verified custom 404 page rendering with clear return navigation.
- **Journey 9: Browser History Traversal**: Verified browser back and forward button state persistence.

### 3.4 Accessibility (axe-core WCAG 2.1 AA) (17 Tests)
- Scanned 15 primary routes with `@axe-core/playwright`.
- **Violations Identified**:
  - `label-content-name-mismatch` on cookie banner consent buttons (`ariaAcceptLabel` mismatching visible text `"Accept All"`).
- **Remediation**:
  - Aligned `ariaAcceptLabel="Accept All"` and `ariaDeclineLabel="Essential Only"` in `components/CookieBanner.tsx`.
- **Final Result**: **0 critical, 0 serious, 0 moderate violations**.
- **Keyboard Navigation**: Confirmed visible `#A7EBC8` mint focus-visible outline rings on all focusable elements during Tab traversal.

### 3.5 Negative & Positive Form Flows (8 Tests)
- **Negative Flows against Production** (`https://turbobytesconsulting.com`):
  - Empty submission: Blocked client-side and server-side with 400 response.
  - Invalid email formatting: Immediate accessible error alert.
  - Honeypot trap (`website` field filled): Request silently dropped; zero spam entries saved.
  - XSS payload (`<script>alert(1)</script>`): Stored safely as escaped plain text; no script execution.
  - Double-click debouncing: Disabled submit button prevents duplicate API calls.
  - Free AI Visibility empty submission: Blocked with appropriate field validation.
- **Positive Flows against Local Dev** (`http://localhost:7000`):
  - Contact form valid submission: Persisted to `ContactQuery` table in database.
  - Free AI Visibility Check valid submission: Persisted to database with `"AI Visibility Check"` service tagging.
